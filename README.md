# 学习目标管理台 · Learning Goal Workspace

一个用来管理**有终点、有总量**的学习目标的单文件网页工作台：不是「每天喝水」那种无限期习惯打卡，而是「背完 2000 个单词」「读完一本 440 页的书」这类**能算完成率、能推算完成日**的目标。

> 在线体验：https://workbuddy.link/p/L30HhSolYCBYhh8kUlLMas
> 手机 / 平板 / 电脑浏览器直接打开即用；手机可「分享 → 添加到主屏幕」当 APP 用。

---

## 功能

### 今日
- 首屏新建目标入口 + 列表底部醒目新建入口
- **今天要处理**：逾期未完成、今天该做的、昨日漏打卡自动滚入今日；黄卡 = 本周休息日，红卡 = 滚入今日
- 目标卡直接打卡：**今日建议量 = 剩余量 ÷ 剩余天数**，预填但可改
- 支持选填**分钟数**、支持**补记最近 6 天**（带「补」标，按真实日期参与连续天数与速度推算）
- 一天可记录多次；支持编辑与二次确认删除
- 逾期目标显示逾期天数，提供「立即打卡」「调整计划」两个出口

### 看板
- 每个目标：进度环、三个核心数字（完成量 / 剩余 / 连续天数）、用户预案、最近 10 条可删除记录
- 手写内联 SVG 的近 14 天投入分钟**分目标堆叠柱状图**（未填分钟的记录不参与堆叠）

### 周报
- 按周一到周日汇总投入量、打卡天数、分钟数，附**上周同口径环比**
- 可翻看历史周，保存「保持 / 问题 / 尝试 / 下周预案」四栏复盘
- 一键生成含环比与四栏内容的周报文本

### 我的
- 在线同步状态与最近同步时间、手动重新同步
- 清空示例数据；输入「清空」清空全部
- 添加到手机主屏幕的三步说明

### 规则细节
- **连续打卡天数**：每周从周一起自动可用 1 个休息日——本周第一次漏打卡不中断，第二次才断
- **预计完成日**：按近 7 天平均速度推算，与截止日比较显示提前/拖后；样本不足时显示「暂无推算」，不编数字
- 目标字段：名称、单位、总量、截止日、配色，外加两个选填字段——「最容易拦住我的障碍」与「如果它出现，我就……」（预案会在卡片上展示）

### 视觉
冷白底 + 紫色渐变主色；绿色成功、红色逾期、琥珀色休息日；目标达成彩带动效；图标全部内联 SVG（无 emoji）。
手机底部四 Tab 单列，平板顶部横向导航，电脑左侧固定边栏 + 多栏布局。

## 数据是真正存在云端的

页面**不是**只把数据放在浏览器 localStorage 里。三张数据表存在 WorkBuddy 资料库空间，页面读写直接走线上：

| 表 | 字段 |
|---|---|
| **学习目标** | 目标名称、单位、总量、截止日期、创建日期、配色、障碍预案、对策、状态、示例数据 |
| **每日打卡记录** | 日期、目标ID、目标名、打卡量、单位、分钟数、补记、示例数据 |
| **每周复盘** | 周起始、保持、问题、尝试、下周预案、示例数据 |

- 新建目标、打卡、补记、删除记录、保存周复盘**全部即时写回云端**
- 换设备、换浏览器打开，数据都在
- 页面**先渲染界面再拉数据**，读取/写入失败有明确提示且可重试，不会白屏、不会静默丢数据

### 同步机制（`sync_layer.js`）

- **cloud-first + 本地缓存**：localStorage 只做缓存与离线暂存，云端为准
- **操作队列**：`enqueueAdd / enqueueUpdate / enqueueDelete`，单飞（single-flight）flush worker 串行落库
- **失败重试**：写入失败每 15 秒自动重试，顶部同步胶囊显示「待同步 N 条」
- **双向同步**：订阅 `onUpdated`，他端改动 600ms 去抖后自动拉取并重渲染
- **输入保护**：重渲染前检查焦点，用户正在输入时不打断（`renderIfIdle`）
- **幽灵写入防护**：`known` 映射区分「已上云记录」与「本地待新增」，临时 id 落库成功后换绑为云端 `_id`，并联动修正队列里引用的目标 ID
- **冲突处理**：以云端为基准合并，保留本地待新增项；孤儿打卡记录先按目标 ID、再按目标名重挂，无主的才丢弃

## 本地构建

```bash
python build_html.py     # 读 src/learning-goal.html → 应用补丁 → 输出 learning-goal-final.html
python smoke_check.py    # 语法校验 + 关键锚点核对 + 渲染函数调用环检查
```

`build_html.py` 的每一步补丁都带锚点断言（`assert count == 1`），锚点错位会直接失败而不是静默产出坏文件。

## 部署到资料库（可选）

产物通过 WorkBuddy 资料库能力导入并发布，数据表随页面挂载：

```
import_html.py   --token-stdin learning-goal-final.html \
                 --file-name "学习目标管理台.html" \
                 --databases '[{"id":"<学习目标表ID>"},{"id":"<打卡表ID>"},{"id":"<周报表ID>"}]'
publish_page.py  --token-stdin --node-id "<页面节点ID>"
```

> 平台凭据（token）只从运行环境读取、经标准输入传递，**不写入任何文件**。

## 安全与隐私说明

- **本仓库不含任何密钥**：无 API Key、无访问令牌、无私钥、无账号密码；推送前已按密钥格式（`ghp_` / `gho_` / `sk-` / `AKIA` / `AIza` / 私钥头等）全量扫描确认
- 产物页面依赖 WorkBuddy 平台在运行时注入的数据访问上下文（`window.__SMART_PAGE__.database`），**页面本身不携带凭据**；脱离平台打开时会自动降级为本地离线模式
- 页面内出现的表 ID / 页面节点 ID 属于**公开页面标识**（发布页源码中本就可见），不是密钥；如不希望复用这些表，重新建表并替换 `build_html.py` 中的 ID 即可
- 发布链接为公网可访问，示例数据均为虚构演示内容，不含真实隐私数据
- `src/learning-goal.html` 为第三方公开 playbook 案例产物，仅作对照参考，如不需要可直接删除
